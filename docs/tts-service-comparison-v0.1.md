# LocalVoice TTSサービス比較メモ v0.1

記録日: 2026-10-06。会話時に確認した公式情報と、今後の比較・機能案を記録する。音声の比較生成・試聴、契約、API接続は未実施。料金・無料枠・提供モデル・商用利用条件は、試聴時と採用時に再確認する。

**採用決定（2026-10-06）: MVPの通常TTSはGoogle Cloud Text-to-SpeechのChirp 3 HDとする。** 具体的な日英の声は同サービス内の試聴で選定する。以下の比較表は選定の検討記録と将来の再検討用に残す。接続・生成・キャッシュ・予算管理の正本は[音声設計](voice-design-v0.1.md)。

## 1. 比較の目的と候補

LocalVoiceでは、土地の小話を長く聞き続けたくなる声を選ぶ。無料枠や単価に加え、日本語・英語の自然さ、地名の読み、抑揚、間、聞き疲れ、生成待ち時間を比較する。以下は料金と能力の整理であり、実聴による音質順位ではない。

MVPの試聴は採用済みのChirp 3 HD内で行い、端末TTSを基準に含める。ElevenLabs、Google Neural2/WaveNet、Cartesia、Fish Audio、Gemini-TTS、CoeFont、VOICEVOX、Kokoro、Azure Speech、Amazon Pollyは将来の再検討候補として同じ表に残す。全サービスの導入・試聴をMVPの必須条件にはしない。

## 3. 比較表に共通する注意点

- 料金は米ドル。税、音声ファイルの保存・配信、サーバー運用、失敗や再試行の費用は別。ただしCoeFontの記録したPlus料金は税込表示。
- 無料枠は利用者ごとに付与される枠として計算しない。Google Cloud TTSは無料枠の利用にも請求設定が必要で、無料枠を超えると課金される。
- 文字数・クレジット・テキストトークン・音声トークンは別の課金単位。モデルや日本語原稿で実測して比較する。Gemini-TTSの音声は1秒25トークンとして計算する。
- 年払いの月換算額、初月キャンペーン、期間限定のモデル割引は、通常月額・継続費用と区別する。
- 商用利用、API利用、保存、アプリ内配信はそれぞれ確認する。一般公開の無料デモを本番APIとして使わない。
- ローカルで実行できることと、スマートフォン内でそのまま動かせることは分けて確認する。音声クローンはMVP必須にしない。

## 4. 原価比較の前提

100万文字を小話数・音声時間・8時間旅行の人日へ換算した仮定の試算は[音声生成量・原価試算](tts-volume-estimate-v0.1.md)を参照する。共有ライブラリの制作費と、利用者ごとの追加生成を分けて計算する。

- 300文字の小話1,000本を1つの声で1回ずつ生成すると30万文字。同じ原稿を3つの声で生成すると90万文字。再試行・読み修正・別言語版は追加で計上する。
- 上記をGoogleの文字課金モデルへ適用する場合、単一声の30万文字は記載の無料枠内。ただし同じ請求単位での他用途の消費や無料枠の共有条件を確認する。
- ElevenLabs/Cartesia/Fish Audioのクレジット課金を、Googleの文字課金と同じ単位として比較しない。使うモデル・原稿・生成秒数で測る。
- 静的な小話は、選定した声ごとに事前生成・保存して再利用する。初期制作費、月間固定費、個人化による追加生成費、保存・配信費を分ける。
- 声を増やすほど生成・保存・検品が増える。再生ユーザー数だけでなく、原稿数×言語数×採用声数×原稿更新頻度を原価の要因として扱う。

## 5. 課金ユーザー向けの音声選択案（未確定）

ユーザー提案: **課金ユーザーが、LocalVoice側で選定したいくつかの音声から好みの声を選べるようにする。** 課金額、提供声数、無料ユーザーとの違い、導入時期は未確定。

MVPの採用TTSはChirp 3 HDに決定したため、まず同サービス内の少数の声で実現する設計とする。日本語3声程度を目安に試聴・選定し、具体的な声IDは試聴後に決める。有料限定にするか、無料で選べる声の数、課金の導入時期は別途決定する。

検討用の初期案:

- 無料ユーザーには品質確認済みの標準音声を提供し、有料ユーザーは追加の少数音声から選べる。例として言語ごとに2〜4声から始め、数は試聴と原価で決める。無料音声の品質を下げることは前提にしない。
- 「落ち着いた」「明るい」「やわらかい」等の声の特徴、表示名、同じ小話の短い試聴を表示する。サービス名・モデル名・クレジット計算を選択操作の中心にしない。
- 選択は言語ごとに保存し、次の案内から反映する。声によって選ばれる話題や事実を変えず、聞き心地を選ぶ機能として扱う。
- 選択肢は運営が品質・商用利用・アプリ内配信・保存条件を確認した許可リストに限定する。提供元の全音声や任意の音声クローンを解放するものではない。
- 採用した声だけを事前生成し、`voice_profile_id`を含む既存のキャッシュ設計で再利用する。Providerの変更はアプリ側の声選択から切り離せるようにする。
- 有料限定にする場合は、一覧・設定保存・音声取得でサーバーが契約状態を確認する。解約・期限切れ・音声提供終了時の標準声への切替表示と、保存済み有料音声の扱いを実装前に決める。

比較時には「声を選べることで聞く時間や継続意向が増えるか」「追加声の制作・運用費が課金収益に見合うか」も確認する。課金機能を年末PoCの必須範囲へ自動的に追加しない。
