# LocalVoice 土地の小話・コンテンツ品質方針 v0.1

更新日: 2026-10-06。仕様・レビュー基準。実装済みではない。

## 1. 体験の中心

位置情報から「検索するほどではないけれど、聞くと面白い土地の小話」が豊富に届くことを中心にする。名所の説明だけでなく、普通の道や移動中にも食・地名・方言・習慣・産業・自然などを扱う。多く聞きたい利用者には、面白さを維持しながら話題の量と種類を増やす。

利用者のRoadWhisper試用では、学校の成り立ちや古いニュースが続き、面白くないと感じた。これは本人の試用観察であり、競合全体の品質や内部実装を断定する根拠ではない。LocalVoiceではこの失敗例をレビューとPoCの比較材料にする。

## 2. 自動案内への採用条件

次を確認して`auto_eligible=true`にする。点数だけで自動合格させず、MVPのseedは人が確認する。

| 観点 | 確認する内容 |
|---|---|
| 土地との関係 | その場所・地域で聞く理由を具体的に説明できる |
| 面白さの理由 | 意外性、身近な疑問への答え、具体的な逸話、暮らしや地域への理解のいずれかがある |
| 具体性 | 汎用的な紹介文や年号の列挙で終わらず、短い話として理解できる |
| 根拠 | 主張と出典が対応し、伝承・事実・現在情報を区別できる |

面白さの理由は編集上の仮説であり、聞き手の反応で見直す。根拠の確度が高いことと、話が面白いことは別の評価とする。

## 3. 通常の自動案内で保留・低優先にする項目

- 学校の開校年・改称・統合などの沿革だけ。
- 現在の地域の暮らし・特徴との関係が薄い過去ニュース。
- 施設の所在地・規模・設置年などの基本情報だけ。
- 地名を入れ替えても成立する汎用説明、同じ内容の言い換え。

上記だけで構成された候補は`auto_eligible=false`とし、通常の自動案内では保留する。興味や質問で必要な場合は別経路で扱う。珍しい学校文化や、過去の出来事が今の街に残した影響など、土地との関係・面白さ・根拠を満たす話へ編集できれば再レビューする。特定カテゴリを一律禁止しない。

最近の記事という理由だけで過去の出来事を「今起きている」と扱わない。発生日、適用期間、確認日を分ける。安全・実用情報は面白さとは別に必要性と鮮度で選ぶ。

## 4. レビュー情報の保存

MVPでは`knowledge_items.metadata_json.story_quality`に保持する。

- `content_kind`: `local_trivia / everyday_culture / origin / anecdote / regional_background / institution_history / past_news / practical`等。
- `why_here`: この場所・適用地域で話す理由。
- `interest_hook`: 聞き手にとって面白いと考えた理由。
- `present_connection`: 過去ニュース等が今の暮らし・地名・地域に残している関係。関係がない場合はnull。
- `auto_eligible`: 通常の自動案内へ採用できるか。
- `hold_reason`: `chronology_only / unrelated_old_news / generic_description / weak_evidence / duplicate`等。
- `reviewed_at`, `reviewer`, `review_version`: 原稿と紐づくレビュー記録。

LLMは候補の整理と原稿化を補助するが、未知の逸話や現在との因果関係を作らない。原稿が変われば再レビューする。面白くするために事実を脚色しない。

## 5. 候補の集め方と話題の量

近隣のPOIだけでなく、適用範囲を設定した地域全体の小話を候補に含める。駅や学校が多い場所でも施設概要ばかりにならないよう、食・生活文化・産業・自然等の種類を確認する。すべてのPOIに一話ずつ作ることを目標にしない。

「よく話す / おしゃべり」は適格な話題をより多く届ける設定にする。面白さ・根拠の条件を下げる設定にはしない。話題が不足した場合は適用可能な地域知識へ候補を広げ、なお不足なら待機して不足を記録する。すでに出した話の言い換えで量を埋めない。

MVPでは宮島・広島・尾道・奈良等の実証地域を事前調査し、地点・地域の適用範囲と出典を設定する。カメラは使わず、実際に見えている対象物の説明として断定しない。

## 6. 評価

同じ地域・知識・移動経路で、近さを中心に選ぶ案内と、この品質条件を使う案内を比べる。音声は揃えて内容の差を評価する。次に内容を揃えて声の差を評価し、原因を混ぜない。

- 面白いと感じた話、もう一度聞きたい話、人に話したい話。
- 設定ごとの小話数、カテゴリの種類、名所以外の話数、候補不足。
- 沿革・古いニュースが選ばれた理由と反応、似た話の繰り返し。
- 地域への理解、聞き続けた時間、不要と感じた通知。

学校の沿革だけ・土地との関係が薄い古いニュースを通常の自動案内から保留できることをseedレビューで確認する。学校文化や街に残る影響の話は、根拠と面白さがあれば採用できることも確認する。量・面白さの合格値は試用後に設定し、機械的な通知数を成功指標にしない。

音声品質は[音声設計](voice-design-v0.1.md)、選択処理は[MVP技術設計](mvp-technical-design-v0.1.md)を参照。
