# LocalVoice 音声品質・TTS比較と設計 v0.1

調査・更新日: 2026-10-06。MVPのTTSはGoogle Chirp 3 HDに採用確定。具体的な声は未選定で、音声生成・試聴・API接続・実機検証は未実施。料金・提供条件は接続時と公開時に再確認する。

## 1. 方針

土地の小話を豊富に聞く体験では、声の自然さ、抑揚、間、聞き取りやすさ、地名の読み、長時間の聞き心地をMVPから扱う。従来の「端末標準TTSを基本にし、音質不足なら後で比較」という方針を変更する。

通常はChirp 3 HDの品質確認済み音声を使い、静的な小話は事前生成・キャッシュする。端末TTSは比較基準と通信断・障害時または利用者が選ぶ代替手段にする。本文の面白さと声の品質は別々に測る。音声を良くしただけで退屈な情報が面白くなるとは判断しない。

## 2. MVPの採用決定と比較記録

2026-10-06、ユーザーの決定により**Google Cloud Text-to-SpeechのChirp 3 HDをMVPの通常TTSとして採用する**。サービスとモデルは確定し、具体的な日英の声ID・表示名は同サービス内の試聴で決める。日本語は3声程度を目安に、言語ごとに標準声と少数の追加声を品質確認して選定する。

全候補の料金・条件は[TTSサービス比較メモの統一比較表](tts-service-comparison-v0.1.md#2-全候補の比較)に残す。他のTTSは将来の品質改善・原価見直し時の候補とし、MVPの接続や公開前検証の必須対象にしない。端末TTSは比較基準と障害・通信断時の代替として残す。Chirp 3 HDの採用は、他サービスより実聴で優れていたという評価を意味しない。

## 3. Chirp 3 HDの原価と予算管理

2026-10-06確認のGoogle公式料金は、月100万文字まで無料枠、超過分は30米ドル／100万文字。請求設定が必要で、無料枠を超えると従量課金される。無料枠をアプリ利用者1人ごとの枠として扱わない。[公式料金](https://cloud.google.com/text-to-speech/pricing)

[100万文字の生成量・原価試算](tts-volume-estimate-v0.1.md)では、1人が8時間旅行する仮案を18,400文字・音声約53分とした。小話と定番の深掘り16,800文字は共有、実用・文脈案内1,600文字は必要時生成の仮定。4地域・日本語3声の共有制作と読み修正予備10%で554,400文字、残り445,600文字で278人日分の追加生成をカバーする。試算であり、件数・声数・キャッシュ率・課金額を仕様上の保証にしない。英語・他用途消費・動的再試行等は追加で計上する。

- APIへ送った実際の文字数、モデル/声/原稿版、成功/失敗/再試行、見積もり生成費をapi_usage_logsへ記録する。Google請求の実費とは区別して照合する。
- 同じ音声の再生ごとに再生成しない。共有の初期制作費と利用者ごとの追加生成費、保存・配信費を分ける。
- 月間生成文字数・費用をアプリ全体で集計し、運営設定の月間予算・リクエスト頻度上限で新規合成を制御する。予算値はPoC開始前に設定する。並行ジョブも見積もり分を予約し、上限を超える新規合成を開始しない。
- 無料枠は停止条件ではない。請求アラートだけでAPI停止されるとは扱わず、アプリ側の上限判定を実装する。新規合成を止めた場合も有効なキャッシュは再生でき、必要なら許可済み端末TTSか文字表示へ移る。

## 4. MVPの実装範囲

- 日英の同じ原稿でChirp 3 HD内の声を比較試聴し、少数を運営の許可リストへ登録する。
- Flutterに音声ファイルの再生/停止/スキップ、声の試聴、言語別の声選択と話速設定を用意する。日本語3声は選定の目安で、具体的な声ID・表示名は未選定。
- FlaskのVoiceProviderにGoogle Cloud TTS用Adapterを実装する。接続先は`global`を初期値とし、Google公式Pythonクライアントの`synthesize_speech`による通常のテキスト合成でMP3を生成・保存・配信する。再生経路は完成した音声ファイルを使い、ストリーミング合成をMVP必須にしない。
- `voice_profile_id`はアプリ内IDとして管理し、Googleの`voice.name`（`<locale>-Chirp3-HD-<voice>`形式）、`language_code`、内部設定版へサーバーで対応付ける。初期対応は`ja-JP`と`en-US`。Providerや任意の声・外部URLを端末から指定させない。
- Google Cloudプロジェクトの請求設定・Cloud Text-to-Speech APIの有効化・Google Cloud認証を接続前に用意する。サーバーではApplication Default Credentialsと実行環境のサービスアカウント等を使い、必要権限に限定する。認証情報をFlutterへ配布せず、リポジトリにも保存しない。
- 静的な日英小話と定番の深掘りは採用声ごとに事前生成し、キャッシュ再利用を先に作る。毎GPS更新で合成しない。個人化した原稿は必要時だけ、利用者が選んだ1声で生成する。
- SSML、合成時の話速・休止・カスタム発音等のPreview機能は必須にせず、通常のテキストと読み上げ用原稿の調整で成立させる。話速のユーザー設定は端末の再生倍率で扱う。

MP3の通常合成、日英の対応、音声名の形式、ADCによる認証は[Chirp 3 HDの公式仕様](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd)に基づく。API接続・声の品質確認・実機での再生は未実施。提供地域やPreview機能を追加する場合は、その時点の対応状況を確認する。

課金ユーザーが運営選定済みの複数音声から選べる案は[TTSサービス比較メモ](tts-service-comparison-v0.1.md#5-課金ユーザー向けの音声選択案未確定)に残す。まずChirp 3 HD内の声で実現する設計とし、無料/有料の提供範囲・価格・課金導入時期は未決定。声の試聴・選択自体はMVPに含める。

## 5. 原稿と読み

画面本文とは別の`speech_text`を原稿版と言語ごとに管理する。音声用に句読点・文の長さ・間を整えても、事実・伝承の区別、必要な注意、意味を変えない。地名、人名、難読語、数字、日英の混在を事前確認する。

読み辞書を版管理し、MVPではChirp 3 HDへ送る音声用原稿の読み仮名置換等に反映する。画面本文は読み用表記へ置き換えない。日本語の固有名詞・英語との混在は個別に試聴する。公式資料でSSMLと音声制御はPreviewのため、利用する場合は日英の対応・入力形式・条件を確認し、内部設定版とキャッシュキーを更新する。生成音声が原稿を省略・追加・言い換えしていないかを試聴で確認し、合成に成功しただけで採用しない。MVPのseed音声は人が確認する。

声は親しみやすい語りを狙い、演技や効果音を増やすこと自体を目的にしない。声優名・第三者の声を模倣する指示、音声クローン、BGM、多人数対話の演出はMVPに含めない。

## 6. 生成・キャッシュ・配信

```text
レビュー済み知識・speech_text・読み辞書
  → VoiceProvider（Google Cloud TTS / Chirp 3 HD / 選定声）
  → AudioAsset・保存/配信
  → Flutter Audio Player・端末キャッシュ
```

キャッシュキーは原稿hash、本文版、読み辞書版、言語、Provider/モデル版/声、スタイル/合成時の話速、音声形式、利用範囲を含む。原稿・読み・モデル設定変更時は別資産にする。端末で再生速度だけを変える場合は合成し直さず、可能な再生倍率で調整する。

MVPの音声資産は通常合成で生成したMP3を基本とし、Content-Typeは`audio/mpeg`、拡張子と実際の音声形式を一致させる。Providerが固定モデル版を公開しない場合は`model_version=provider-managed`とし、公開されていない版を固定した扱いにしない。Googleの実際の声名・接続先・生成日時と内部設定版を記録する。

共有音声は個人情報を含まない静的原稿に限る。個人の会話・プロフィールを使う音声はuser/trip単位で分離し、短い保持期限を設定する。TTSへは必要な原稿と音声設定だけ送り、生GPS・認証情報・全会話履歴は送らない。利用条件が保存・再配信を許す範囲でキャッシュする。

同じキーの同時生成は一つのジョブへ集約する。上限・タイムアウト・再試行回数を設定し、各Providerの実際の課金を記録する。事前生成は選定声だけを対象にして無用な全声生成を避ける。

音声は認証されたAPIか短期限の配信URLで取得する。個人音声は取得時に所有者を確認し、URLや音声を共有ログへ載せない。端末はuser_idでキャッシュを分離し、ログアウト・アカウント切替・削除・期限切れで個人音声を除去する。

本文の有効期限・削除・訂正を音声にも適用する。通信断中も期限切れ音声は再生しない。外部の署名URLが期限切れでも、保存済み音声は本文の有効性・利用者権限・保持期限で判断する。

## 7. 待ち時間・障害・再生

採用した声の有効なキャッシュがあれば先に使う。生成待ち上限はPoCの初期値5秒とし調整する。間に合わなければ、事前に許可した端末TTSか文字表示へ移る。通常の声から代替に切り替わった状態を表示し、予期しない声の変化を隠さない。

再生要求にgeneration tokenを持ち、停止・スキップ・次の案内・セッション終了・ログアウトで無効化する。遅れて届いた音声で二重再生や停止後の再開をしない。一度端末TTSへ移った同じ案内を、後から高品質音声で自動再生し直さない。音声の直列キューと取得処理を分け、通話・他アプリの音声・Bluetooth切断に応じて停止/復帰を実機確認する。

生成障害が本文・地図・位置履歴を停止させない。音声OFFの利用者には無用な個別合成を行わない。

## 8. 比較試聴と採用条件

レビュー済みの実証地域の原稿を、日本語10本・英語10本用意する。20〜40秒程度の小話、1〜2分の詳しい話、地名/方言/人名、数字、伝承の断り、日英混在を含める。声の好みを比較する試験では音量と再生環境を揃え、提示順を変える。

1. 同じ原稿で端末TTSとChirp 3 HD内の候補音声を比較し、自然さ・聞き取り・抑揚/間・読み・疲れにくさ・好みを記録する。
2. 初期基準は自然さと聞き取りで5段階の中央値4以上、意味が変わる誤読や原稿の欠落/追加なし。20〜30分の連続試聴でも評価する。声の好みは日英別・人別に残し、基準は記録を伴って調整する。
3. 同じ声で小話の内容を評価し、面白さの不足を声で隠さない。
4. iPhone/Androidの端末スピーカーとイヤホンで、停止・通信断・キャッシュ・代替・遅着・ログアウト時の挙動を確認する。
5. 生成待ち時間、出力音声秒数、cache hit、失敗/再試行、話数、固定費と従量費、1旅行の原価を記録する。

MVPのサービス採用はChirp 3 HDに確定している。具体的な声の公開前に、Google Cloudの契約・配信/保存条件、日英の品質、原稿忠実性、原価・待ち時間、障害時の動作を確認する。音質基準に届かない声は原稿・読み・候補声を調整し、それでも満たせない場合に将来候補との比較を再開する。他サービスとの網羅的な比較をMVP実装の開始条件にしない。
