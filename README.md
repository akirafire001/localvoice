# LocalVoice

**現在地・移動状況・ユーザーの興味を理解して、「今ここで知ると面白いこと」を届ける位置情報AIガイド。**

LocalVoice は、一般的な観光スポット検索アプリではありません。

スマートフォンの位置情報、移動方向・速度、時間、天候、ユーザーの趣向や知識、同行者、直前の会話などを組み合わせ、AIが **「今、この人に、この場所で何を伝えると面白いか」** を判断し、文字・通知・音声で届けることを目指します。

## コンセプト

旅行や散歩をしていると、目の前には建物、地形、川、山、植物、看板、路地、食文化、地域産業など大量の情報があります。しかし、自分が知らないものは検索することすらできません。

LocalVoice は、そうした **「自分では気づかなかった現実世界の面白さ」** をAIに見つけてもらうことを狙っています。

重要なのは情報量ではなく、**何を選び、いつ話し、いつ黙るか** です。

## 想定する体験

例えば街を歩いているときに、次のような情報を状況に応じて届けます。

- この地域で特定の屋根や建築様式が多い理由
- 建物が建てられた時代と、その時代背景
- 地名、川、山などの名前の由来
- 周辺に生息する動植物とその生態
- 地質、鉱石、地形の特徴
- 郷土料理や名産品が生まれた理由
- 方言や地域独特の文化
- 地場産業と街の形成の関係
- 今日だから見られるイベント、季節、潮汐、天候等の情報
- 現在地から見える、またはこれから見えてくる山・島・建物等

ユーザーが特定の話題に興味を示した場合は、しばらく関連情報を厚めにすることも想定しています。

## 主な特徴

- ユーザーごとの趣向・知識レベルを考慮
- 旅行、散歩、出張、通勤など現在の状況を考慮
- 日本語・英語等の多言語対応を想定
- グループ旅行と個人旅行の両方を想定
- GPS履歴から速度・進行方向を推定
- 徒歩、車、鉄道、船等に応じて情報探索範囲を変更
- 長期的な趣向と「今この話が面白い」という短期的興味を分離
- 趣向外の情報も一定割合で混ぜるセレンディピティ機能
- 文字、OS通知、音声による情報提供
- 情報の信頼度や出典を管理
- 伝承・都市伝説等も、確度を明示した上で扱う
- 静的な知識DBとリアルタイム情報を組み合わせ、AI/APIコストを抑制

## 技術構成（予定）

| 領域 | 技術 |
| --- | --- |
| モバイル | Flutter |
| 対応OS | Android / iOS |
| APIサーバー | Python / Flask |
| Database | PostgreSQL |
| 地理情報 | PostGISを想定 |
| AI | LLMを用途に応じて利用 |
| 音声 | TTS |

LLMにすべてを処理させるのではなく、距離計算、速度・方向判定、候補抽出、通知間隔、重複排除、興味スコア等は通常のプログラムで処理し、**人間的な判断が必要な部分にLLMを利用する**方針です。

## 最初の目標

年末の実旅行でドラフト版を実際に使用し、技術的完成度よりもまず、

> **位置情報に合わせてAIから知らなかった話を聞く体験は、本当に面白いのか？**

を検証します。

初期版ではGPS取得、位置付き知識DB、周辺情報選択、日本語・英語、テキスト通知、音声読み上げ、興味フィードバック、速度・方向判定、短期コンテキスト等を優先します。

## 要検討事項

特に以下はPoCを通して検証します。

- LLM / Web検索 / TTS / 翻訳 / 地図API等の利用コスト
- 1人が8時間旅行した場合のAPI原価
- 情報源と信頼性評価方法
- 静的知識DBとリアルタイム検索の役割分担
- iOS / Androidのバックグラウンド位置情報制約
- バッテリー消費
- 通知頻度と「うるささ」の最適化
- 課金方式
